# threads_demo_NUM_THREADS_worker.c

** Вивiд програми **

`Потік 0: часткова сума = 15`
`Потік 1: часткова сума = 5015`
`Потік 3: часткова сума = 15015`
`Потік 7: часткова сума = 35015`
`Потік 2: часткова сума = 10015`
`Потік 5: часткова сума = 25015`
`Потік 6: часткова сума = 30015`
`Потік 4: часткова сума = 20015`
`Загальна сума: 140120`

`Функція потоку отримує вказівник на структуру Job, кожен потік працює з власним елементом масиву для уникання конфліктів у пам'яті, а порядок виводу змінюється через особливості роботи планувальника операційної системи. Функція worker отримує вказівник на структуру Job (точніше, нетипізований вказівник void *arg, який усередині функції приводиться до типу Job *). Функція worker отримує вказівник на відповідний елемент масиву структур jobs[i]. У функції main під час виклику pthread_create цей вказівник передається як четвертий аргумент. Оскільки він має універсальний тип void *, всередині функції потоку ми приводимо його назад до потрібного нам типу: Job *job = (Job *)arg;. Це дозволяє потоку знати свій порядковий номер (job->index) та записати туди результат обчислень (job->result). Кожному потоку виділяється окремий елемент масиву, щоб уникнути стану гонитви race condition та перезапису даних.`
`Потік N: ...» може змінюватися між запусками Це відбувається через асинхронність та роботу планувальника операційної системи. Коли стартують потоки вони починають виконуватися паралельно. Операційна система сама вирішує, якому потоку і в яку мікросекунду виділити квант процесорного часу. Який потік швидше отримає ресурси та дійде до команди printf, той і виведе свій рядок першим.`

# sum_array.c

** Вивiд програми **

`Сума 1..100 = 5050`

`Кожен потік працює у власній ізольованій ділянці пам'яті для запису, а спільний масив використовується виключно для читання.`
`Чому кожен потік змінює лише власну структуру slices[t] Це забезпечується завдяки передачі унікальної адреси під час створення потоку:`
`У головному потоці створюється масив структур Slice slices[NUM_THREADS]. Кожен елемент цього масиву розташований за своєю унікальною адресою в пам'яті.`
`У циклі pthread_create ви передаєте в кожен потік вказівник саме на його елемент: &slices[t].`
`Всередині функції потоку рядок Slice *s = (Slice *)arg; отримує цей унікальний вказівник. Коли потік виконує s->sum = 0; або s->sum += ..., він модифікує комірку пам'яті, яка належить тільки йому. Жоден інший потік не має доступу до цієї адреси, тому вони не заважають один одному.`
`Стан гонитви виникає лише тоді, коли щонайменше два потоки одночасно звертаються до однієї комірки пам'яті, і при цьому хоча б один із них виконує запис.`
`у цiй програмi : Тільки читання: Усі робочі потоки у циклі sum_slice лише читають значення з масиву data (... += data[i]). Жоден робочий потік нічого туди не пише. Поділ за індексами: Хоча масив data є спільним (глобальним), завдяки математичному розподілу індексів start та end потоки навіть не читають однакові елементи одночасно — кожен потік обробляє свій власний "шматочок" (slice) масиву. Послідовність виконання: Головний потік заповнює масив data до того, як викликає pthread_create. Відповідно, на момент старту потоків дані в масиві вже стабільні й не змінюються.`
